# Adaptive Pergola 0.7.1

Custom-position rules can now use separate activation and release conditions to prevent repeated roof movements when a measurement fluctuates around a threshold.

## Hysteresis

- All ten slots have an optional **Release template (hysteresis)** in their settings, with English, German and French labels and help text.
- An activated rule stays active until its release condition becomes true. If both conditions are true, activation takes precedence.
- The retained state survives integration reloads and Home Assistant restarts. Disabling a slot or changing its definition resets that state; unrelated settings preserve it.
- Release conditions are tracked independently, so a release takes effect even when the activation condition remains false. Existing priority-100 activation/release behavior outside the active time window is preserved.
- A release-template rendering error retains the active state. Use explicit numeric guards for sensors that can become unavailable.
- Decision traces show `hysteresis hold` while the rule is retained between thresholds.
- The `set_custom_position` service accepts `release_template`; generic options accept `custom_position_release_template_1` through `_10`.

## Configure a 4–5 °C band

Keep your cold-weather activation condition below 4 °C and add a release condition at or above 5 °C. Replace the example entity with your temperature sensor:

**Activation:**
```jinja
{{ is_number(states('sensor.outdoor_temperature'))
   and states('sensor.outdoor_temperature') | float(99) < 4 }}
```

**Release:**
```jinja
{{ is_number(states('sensor.outdoor_temperature'))
   and states('sensor.outdoor_temperature') | float(0) >= 5 }}
```

Existing rules remain unchanged until a release template is configured. Clearing it restores immediate deactivation when the original trigger becomes false.
